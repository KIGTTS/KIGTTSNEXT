# 插件界面规范

先把用户最常做的事放到页面正文。顶栏用于返回、标题和少量全页操作，例如整个页面的搜索或保存。导入、导出、运行、预览和条目编辑各自放在相关卡片或列表行里。多步任务跳到独立页面，谈得清的一项选择或确认用弹窗。

## 用宿主的控件

- 原生插件用 `PageBlock.Group` 把有关设置组成卡片，Lua 使用模板里的 `type='group'` 和 `children`。组标题说清里面是什么。涉及同一个选项时，用宿主的单选、开关或滑条。
- 组内的 `Actions` 放相关按钮。只有明确需要在顶栏常驻的全页操作才用 `headerAction` 或顶层操作块。
- 列表的名称、图标和简短状态放在行内。使用原生管理列表做排序和行菜单。先让用户能看清楚要操作哪一项，再提供编辑、分享或删除。
- 使用宿主主题色、字体、圆角、相邻圆角和图标。文字、图标和点击区域一起对齐，浅色与深色都检查。网页工具使用示例里的安全区、主题变量和触感接口。
- 快捷文本网页默认保持宿主按钮清晰。用户手动选择沉浸时，在对应控件上用 `KigttsPresentation.setControls` 按组启停淡化。用宿主 API 进入和退出全屏，处理无接口和拒绝授权。参见[快捷文本网页示范](quick-text-web.md)。

## 布局和文案

- 让页面在窄屏和横屏都能滚动，文字较长时允许换行，常用动作应当一眼可见。
- 文案和操作结果放在插件自身语言包。覆盖简体中文、简体中文（轻松版）、英文、日文和韩文。把示例中的标签换成用户能理解的动作名称。
- 用「插件模板」验证页面合同、按钮动作和各状态。至少检查加载、空列表、错误反馈、返回、窄屏，以及一种翻译后较长的语言。
