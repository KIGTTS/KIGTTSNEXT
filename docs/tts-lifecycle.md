# 合成引擎生命周期与低延迟输出（API9）

模型、发音转换器、平台 TTS 连接和空闲回收都由插件拥有；主 APK 只传输标准状态、控制与 PCM，不包含引擎、模型或发音字典。未来的合成提供者遵循相同约定。

## 生命周期

`TtsInfo.supportsControl=true` 表示支持 `TtsEngine.control(TtsControl)`。合成服务通过 `SpeechBroker.control(pluginId, command)` 向提供者传递以下操作：

| 操作 | 行为 |
| --- | --- |
| `PREPARE` | 为 `voiceId` 提前建立可复用资源，不合成或播放声音；重复操作应复用相同资源 |
| `RELEASE` | 释放当前模型/连接，保留包、语音文件和配置；即使保持加载也必须释放。下一次请求仍可重新建立资源 |
| `SET_RESIDENT` | `resident=true` 取消空闲释放；false 恢复两分钟空闲计时，不主动加载已释放的资源 |
| `ACTIVITY` | `active=true` 表示播放器正在发声，禁止空闲释放；false 从播放结束开始计时 |

`close()` 是插件卸载/停用/工作进程结束的最终释放。请求取消只释放本次 tensor、结果、音频监听和临时文件；缓存仍可复用。插件必须串行保护实际合成资源，不得在活动推理、流式输出或播放期间因空闲超时关闭模型。明确切换引擎仍可以释放旧资源。

`PluginContext.automaticRead` 和 `ttsPluginId` 是宿主的自动朗读设置与实际选用插件；`speechActive` 是实际播放状态。宿主异步合并上下文，在自动朗读开启或选用插件改变时预热一次，新文字和普通页面刷新不会反复预热。关闭自动朗读后保留已加载资源，继续受空闲超时管理。

提供者 DTO 的 `generation` 标识本次工作进程实例。重启后合成服务重新传递当前常驻策略和准备指令，不能假设旧实例仍持有缓存。

## 统一设置

“保持加载”只放在语音合成服务页面，保存到该插件的 `config/service.json`，默认关闭。它应用于当前选用引擎以及本次必要的系统保底连接，不绑定某个 Piper 语音包。开启后，已经使用/预热过的当前引擎保持加载；切换至其它引擎仍先释放旧引擎，不会因此保留全部模型。

选用 Piper 后，第一次手动朗读按需加载；自动朗读开启时提前加载。使用过同一引擎后换语音包会释放旧包、准备新包，换 speaker 可以复用同一模型。普通语速改变不重建模型。未使用且自动朗读关闭时不提前加载。

默认从合成/播放结束后的空闲期计时，120 秒释放。开启保持加载取消这个超时；资源被明确释放、包更新、引擎停用或进程退出时，不受常驻设置阻止。手机系统也可以回收整个进程，常驻不是后台保活保证。

## 插件实现

`engine-plugins/tts-support` 是独立引擎依赖，提供 `ResidentResource` 和 `speechSegments`，只装入专用包。缓存采用单资源与串行租用：一个提供者最多保留当前模型/平台连接。新的键值先关闭旧资源；活动租用期间暂停空闲回收；取消后保留可用缓存，真正失败后销毁可疑资源。

Piper 复用 `OrtSession` 与绑定的发音转换器。模型、配置、词典、manifest 的路径/尺寸/更新时间及转换参数构成缓存键。导入、删除和刷新命令显式失效。每段 tensor/result 单独关闭，ORT 环境和原生数据不传入宿主。

长文本首段最多 32 个 UTF-16 单元，后续段最多 96 个，优先句末标点、其次词或逗号边界，不拆代理对，不丢失文本。每段一完成即输出 PCM；一次调用只发送一个 Started/Finished。Piper 单次上限仍为 500 字符，合成服务按提供者上限继续拆分更长文本；服务在已输出音频后遇到错误不会回退重读此前文字。

系统 TTS 是合成服务内置保底，不独立分发；它复用 `TextToSpeech` 连接，语言与音色跟随系统默认，仅设置用户统一语速。通过 [UtteranceProgressListener](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener#onAudioAvailable(java.lang.String,%20byte[])) 的音频回调即时传 PCM，支持 8/16 位和 float 转换及帧对齐。不提供回调或格式无法转换的系统引擎，回退读取当前短段的 WAV；不会等待整篇文本生成 WAV。监听按 utterance token 隔离，取消停止本次请求并删除插件临时文件。

## 升级与验证边界

当前 SDK 为 API9，外置包统一 0.8.0。必须先更新宿主，再同发布者升级专用包；已有模型、资源、配置和启停状态保留。API8 及更早的二进制不与 API9 混用。管理器协议仍为 1，无需因此重装管理器或测试 APK。生命周期协议最初在 API8 加入，下面保留该版历史测量。

单元回归验证复用、换包/进程失效、取消和失败清理、120秒/活动播放/常驻、路由释放、首段先输出、Unicode 分段和 Binder 授权。2026-10-12 在 23113RKC6C 上安装 API8：同一 Piper 工作进程和模型连续复用，默认约 120 秒释放，保持加载超过 173 秒未释放，切换系统声音仍立即释放 Piper。短文本首 PCM 冷启动 2350 ms（模型加载 1912 ms），两次复用为 765/627 ms；132 字符长文本首 PCM 267 ms、合成完成 3870 ms。系统保底两次首 PCM 445/389 ms，平台连接只建立一次，返回 Piper 时释放。

上述为单设备少量真实合成样本，来源于插件耗时日志；管理器自检不播放声音，不包含最终 AudioTrack 或蓝牙延迟。不能与此前包含 ADB 的完整自检时长直接比较。临时声音和保持加载设置已恢复。插件日志只记录资源加载/释放、长度和耗时，不记录文本、文件路径或声音内容。


API9 当前构建与设备结果统一见 [Release 验证记录](release-testing.md)。上述 2026-10-12 测量仅代表当时版本和设备，不能据此声称新 Agent/Lua/商店/构建功能已经完成手机验收。

## API21 语音包设置

语音合成服务0.8.1与Piper0.8.1使用API21。服务的声音入口打开语音包页面，语速以原生滑条统一保存；当前语音包在独立卡片显示自身支持的参数，语音条目菜单可打开同组弹窗。Piper音量、音色变化和节奏变化保存在包内元数据，更新包与导出仍保留，切换包不会相互覆盖；语言直接取包配置，不使用服务手选语言。系统声音仅有系统默认声音，说明为系统语音合成，不枚举中英文或覆盖系统语言。
