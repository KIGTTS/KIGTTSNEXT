# 用户界面文案

面向用户的说明写用途、操作和结果。避免在介绍或副标题中解释内部结构，例如宿主、接口、进程、桥接、持久化、模块拆分与资源目录。

- 按钮使用具体动作，例如“添加源”“确认并下载”“继续安装”。提示应解释当前情况和下一步。
- 重复添加来源时说明“已经添加过了”，展示已有来源，保留原来的启用状态。
- 副标题只补充必要信息；分类标签用于分类，功能介绍放在正文。
- 权限页说明会读取什么、发送给谁、用于什么。格式、设备兼容、许可证与不可恢复操作的说明应准确保留。
- 开发工具、日志、Agent 工具合同和源代码注释可以保留必要技术术语，不把它们直接用于产品介绍。
- 文案检查覆盖安卓界面、插件包内页面和清单、商店目录、KPM 网站及空白、错误、完成状态。
